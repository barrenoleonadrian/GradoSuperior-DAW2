Programación Orientada a Objetos (OOP)

La OOP es una forma de organizar el código agrupando datos y funciones que trabajan juntas dentro de clases. En vez de tener funciones sueltas, creamos objetos que representan cosas del mundo real.

💡
Analogía: Una clase es el molde. Un objeto es lo que fabricas con ese molde. Si la clase es Coche, un objeto sería miCoche (un Ford Rojo del 2020).

Las ventajas principales que usamos en clase son:

  • Reutilización: escribes la clase una vez y la usas en muchos sitios.
  • Organización: cada clase tiene una responsabilidad clara (Modelo, Controlador, Vista...).
  • Encapsulación: los datos internos están protegidos del exterior.
1.1

Clases y objetos

Una clase se define con class. Tiene propiedades (variables) y métodos (funciones). El método especial __construct() se llama automáticamente al crear el objeto con new.

// Definimos la clase Mascota
class Mascota {

    // Propiedades (variables de la clase)
    public $nombre;
    public $tipo;
    private $edad;   // privada: solo accesible desde dentro de la clase

    // Constructor: se ejecuta al hacer "new Mascota(...)"
    public function __construct(string $nombre, string $tipo, int $edad) {
        $this->nombre = $nombre;   // $this hace referencia al objeto actual
        $this->tipo   = $tipo;
        $this->edad   = $edad;
    }

    // Método público
    public function presentarse(): string {
        return "Soy {$this->nombre}, un {$this->tipo} de {$this->edad} años.";
    }

    // Getter para la propiedad privada $edad
    public function getEdad(): int {
        return $this->edad;
    }
}

// Crear un objeto (instanciar la clase)
$mascota1 = new Mascota('Rallito', 'tortuga', 8);
$mascota2 = new Mascota('Carl', 'gato', 10);

echo $mascota1->presentarse(); // "Soy Rallito, un tortuga de 8 años."
echo $mascota2->nombre;          // "Carl" (propiedad pública)
// echo $mascota1->edad;  ← ERROR: propiedad privada
✅
Buena práctica: Las propiedades casi siempre deben ser private o protected. Se accede a ellas mediante métodos getter y setter. Esto es encapsulación.
1.2

Visibilidad: public, protected, private

Es uno de los conceptos más importantes del examen. Define desde dónde se puede acceder a una propiedad o método:

Modificador¿Desde dónde se puede acceder?Cuándo usarlo
publicDesde cualquier sitioMétodos que el exterior necesita llamar
protectedDesde la propia clase y sus hijasMétodos/propiedades que heredarán las subclases
privateSolo desde la propia claseDatos internos que nadie debe tocar directamente
finalNo puede ser sobreescrito en hijasCuando un método NO debe modificarse
abstractNo puede usarse directamente, hay que heredarForzar a las clases hija a implementar el método
class Animal {
    public    $nombre;     // accesible desde cualquier lado
    protected $raza;       // accesible desde Animal y sus hijas
    private   $microchip;  // solo accesible dentro de Animal
}

class Perro extends Animal {
    public function info() {
        echo $this->nombre;    // ✅ public
        echo $this->raza;      // ✅ protected (es clase hija)
        echo $this->microchip; // ❌ ERROR: private de Animal
    }
}
1.3

Herencia

La herencia permite crear una clase nueva (hija) que reutiliza todo lo de otra clase (padre/madre). En PHP la herencia es simple: una clase solo puede heredar de UNA clase padre.

Se usa la palabra extends. Desde la clase hija puedes acceder a métodos del padre con parent::.

// Clase padre (base)
class Controlador {

    // Método que heredarán todos los controladores
    public function modelo(string $nombre) {
        $fqcn = 'Dwes\\Clinica\\' . ucfirst($nombre);
        return new $fqcn();
    }

    public function vista(string $vista, array $datos = []) {
        extract($datos);  // convierte el array en variables
        require RUTA_APP . '/vistas/' . $vista . '.php';
    }
}

// Clase hija: hereda modelo() y vista() automáticamente
class Personas extends Controlador {

    public function index() {
        // Usamos modelo() que viene heredado de Controlador
        $modeloPersona = $this->modelo('Persona');
        $personas = $modeloPersona->getPersonas();

        // Usamos vista() que también viene heredada
        $this->vista('personas/index', ['personas' => $personas]);
    }
}

// También puedes sobreescribir (override) un método del padre
class Mascotas extends Controlador {

    // Sobreescribimos el método modelo() con comportamiento distinto
    public function modelo(string $nombre) {
        echo "Cargando modelo: {$nombre}";
        return parent::modelo($nombre);  // llamamos al padre
    }
}
🧠
En nuestro proyecto: Controlador es la clase padre. Paginas, Personas, Mascotas y Api son las clases hijas que heredan de ella. De ahí el class Personas extends Controlador.
1.4

Clases Abstractas

Una clase abstracta es una clase que no puedes instanciar directamente (no puedes hacer new ClaseAbstracta()). Sirve de molde base que obliga a las clases hijas a implementar ciertos métodos.

  • Si una clase tiene al menos un método abstract, la clase entera debe ser abstract.
  • Los métodos abstractos solo declaran la firma (nombre y parámetros), sin cuerpo.
  • La clase hija está obligada a implementar todos los métodos abstractos del padre.
// Clase abstracta: define el "contrato" que deben cumplir todas las formas
abstract class Figura {

    // Propiedad que sí puede tener (a diferencia de una interfaz)
    protected string $color;

    // Constructor normal con implementación
    public function __construct(string $color) {
        $this->color = $color;
    }

    // Método con implementación (lo heredan las hijas directamente)
    public function getColor(): string {
        return $this->color;
    }

    // Método abstracto: sin cuerpo. La clase hija DEBE implementarlo.
    abstract public function area(): float;
}

// Clase hija: OBLIGADA a implementar area()
class Circulo extends Figura {
    private float $radio;

    public function __construct(float $radio, string $color) {
        parent::__construct($color);  // llamamos al constructor del padre
        $this->radio = $radio;
    }

    // Implementamos el método abstracto obligatorio
    public function area(): float {
        return M_PI * $this->radio ** 2;
    }
}

// $f = new Figura('rojo');  ← ❌ ERROR: no se puede instanciar una abstracta
$c = new Circulo(5.0, 'azul');  // ✅
echo $c->area();       // 78.53...
echo $c->getColor();  // "azul"
1.5

Interfaces

Una interfaz define un contrato: dice qué métodos debe tener una clase, pero no cómo los implementa. A diferencia de las clases abstractas:

CaracterísticaInterfazClase Abstracta
Instanciar❌ No❌ No
Propiedades❌ No puede tener✅ Puede tener
Métodos con código❌ Solo declaración✅ Puede tener
Herencia múltiple✅ Una clase puede implementar varias❌ Solo una clase padre
Visibilidad métodosSolo publicPublic o protected
Palabra claveimplementsextends
// Definimos la interfaz
interface Guardable {
    public function guardar(): bool;   // sin cuerpo
    public function eliminar(): bool;
}

interface Validable {
    public function validar(): bool;
}

// Una clase puede implementar VARIAS interfaces (herencia múltiple)
class Persona implements Guardable, Validable {

    public function guardar(): bool {
        // aquí la lógica real para guardar en BD
        return true;
    }

    public function eliminar(): bool {
        return true;
    }

    public function validar(): bool {
        return !empty($this->nombre);
    }
}
1.6

Traits

Los traits son un mecanismo de reutilización de código que suple la falta de herencia múltiple en PHP. Un trait agrupa métodos que puedes "pegar" en varias clases independientes.

⚠️
Un trait NO se puede instanciar directamente (new MiTrait() da error). Solo sirve para incluirlo en una clase con use.
// Trait: bloque de métodos reutilizables
trait Registrable {
    public function log(string $mensaje): void {
        file_put_contents('log.txt', date('Y-m-d H:i:s') . ' - ' . $mensaje . "\n", FILE_APPEND);
    }
}

trait Timestamps {
    public function ahora(): string {
        return date('d/m/Y H:i:s');
    }
}

// Usamos DOS traits en una sola clase
class Veterinario {
    use Registrable, Timestamps;  // incluimos los dos traits

    public function atender(string $paciente): void {
        $this->log("Atendiendo a {$paciente} a las " . $this->ahora());
    }
}

$vet = new Veterinario();
$vet->atender('Rallito');  // Escribe en log.txt

Namespaces (Espacios de nombres)

Los namespaces sirven para organizar el código y evitar colisiones de nombres. Imagina que dos librerías distintas tienen una clase llamada Database. Con namespaces, una puede ser MiApp\Database y otra OtraLib\Database.

En nuestro proyecto usamos el namespace Dwes\Clinica definido en composer.json.

// Al inicio de CADA archivo PHP, declaramos su namespace
namespace Dwes\Clinica;

// Para usar clases de otro namespace, usamos "use"
use Dwes\Clinica\Controlador;
use PDO;  // PDO está en el namespace global

class Personas extends Controlador {
    // ...
}

En composer.json le decimos a Composer dónde buscar las clases de nuestro namespace:

{
  "autoload": {
    "psr-4": {
      "Dwes\\Clinica\\": [
        "app/librerias",
        "app/controladores",
        "app/modelos"
      ]
    }
  }
}
🔄
Después de modificar composer.json, hay que ejecutar composer dump-autoload en la terminal para que regenere el autoloader.

Métodos Mágicos

Son métodos especiales que PHP llama automáticamente en ciertas situaciones. Empiezan siempre con __.

Método¿Cuándo se llama?Uso típico
__construct()Al hacer new Clase()Inicializar propiedades
__destruct()Cuando el objeto deja de usarseCerrar conexiones, liberar recursos
__toString()Al usar el objeto como string (echo $obj)Representación textual del objeto

__set($name, $val)Al intentar escribir propiedad inaccesibleSetters dinámicos
class Mascota {
    private array $datos = [];

    public function __construct(string $nombre) {
        $this->datos['nombre'] = $nombre;
    }

    // Se llama cuando hacemos "echo $mascota"
    public function __toString(): string {
        return "Mascota: {$this->datos['nombre']}";
    }
}

$m = new Mascota('Carl');
echo $m;  // Mascota: Carl  (llama a __toString automáticamente)

Patrón Modelo Vista Controlador (MVC)

MVC es un patrón de diseño que divide la aplicación en tres capas con responsabilidades distintas. El objetivo es separar la lógica de negocio de la presentación.

NAVEGADOR → petición → CONTROLADOR
                                      ↕ pide datos ↕
VISTA (HTML) ← respuesta ← CONTROLADOR ↔ MODELO (BD)
CapaArchivoResponsabilidad
Modeloapp/modelos/Persona.phpAccede a la BD. Contiene las consultas SQL.
Vistaapp/vistas/personas/index.phpSolo muestra datos. HTML + PHP mínimo.
Controladorapp/controladores/Personas.phpCoordina modelo y vista. Lógica de negocio.
2.1

Flujo completo de una petición

Cuando el usuario escribe http://localhost/mvcrecuperacion/public/personas/index, esto es lo que ocurre paso a paso:

  1. El servidor web recibe la petición y el .htaccess la redirige a public/index.php.
  2. index.php carga el autoloader de Composer y crea una instancia de Core.
  3. Core analiza la URL: personas → controlador, index → método.
  4. Core instancia Personas y llama a Personas::index().
  5. index() usa el modelo Persona para obtener los datos de la BD.
  6. index() llama a la vista personas/index.php pasándole los datos.
  7. La vista genera el HTML y lo envía al navegador.
// ① public/index.php – Punto de entrada único
require_once __DIR__ . '/../vendor/autoload.php';
require_once __DIR__ . '/../app/config/config.php';

use Dwes\Clinica\Core;
$iniciar = new Core();  // Core lee la URL y enruta

// ② app/librerias/Core.php – El enrutador
// URL: /personas/index  →  controlador=Personas, método=index
// URL: /personas/ficha/3  →  controlador=Personas, método=ficha, param=3

$url = explode('/', $_GET['url']); // ['personas', 'index']
$controlador = ucfirst($url[0]);    // 'Personas'
$metodo      = $url[1] ?? 'index';   // 'index'
$parametro   = $url[2] ?? null;      // 3 (o null si no hay)

$obj = new $controlador();
call_user_func_array([$obj, $metodo], [$parametro]);
2.2

El Modelo

El modelo es la capa que habla con la base de datos. Contiene solo consultas SQL. No sabe nada de HTML ni de la lógica de la aplicación. Usa la clase Db del framework para hacer consultas preparadas con PDO.

namespace Dwes\Clinica;

class Persona extends Controlador {

    private Db $db;

    public function __construct() {
        $this->db = new Db();  // clase del framework que envuelve PDO
    }

    // ── SELECT todos ──
    public function getPersonas(): array {
        $this->db->query('SELECT * FROM personas ORDER BY nombre');
        return $this->db->registros(); // array de objetos stdClass
    }

    // ── SELECT uno por id ──
    public function getPersonaPorId(int $id): ?object {
        $this->db->query('SELECT * FROM personas WHERE id = :id');
        $this->db->bind(':id', $id);  // bind evita inyección SQL
        return $this->db->registro(); // un objeto o null
    }

    // ── INSERT ──
    public function insertarPersona(string $nombre, string $apellidos,
                                     string $telefono, string $email): bool {
        $this->db->query(
            'INSERT INTO personas (nombre, apellidos, telefono, email)
             VALUES (:nombre, :apellidos, :telefono, :email)'
        );
        $this->db->bind(':nombre',    $nombre);
        $this->db->bind(':apellidos', $apellidos);
        $this->db->bind(':telefono',  $telefono);
        $this->db->bind(':email',     $email);
        return $this->db->execute();
    }

    // ── DELETE ──
    public function eliminarPersona(int $id): bool {
        $this->db->query('DELETE FROM personas WHERE id = :id');
        $this->db->bind(':id', $id);
        return $this->db->execute();
    }
}
🚨
NUNCA hagas esto: query("SELECT * FROM personas WHERE id = $id"). Las variables directas en SQL permiten inyección SQL. Siempre usa instrucciones preparadas con bind().
2.3

El Controlador

El controlador es el cerebro de la aplicación. Recibe la petición del usuario, llama al modelo si necesita datos, valida los formularios y envía los datos a la vista.

namespace Dwes\Clinica;
use Dwes\Clinica\Controlador;

class Personas extends Controlador {

    public function __construct() {
        // Seguridad: si no hay sesión, al login
        if (session_status() === PHP_SESSION_NONE) session_start();
        if (!isset($_SESSION['veterinario_id'])) {
            header('Location: ' . RUTA_URL . '/paginas/login');
            exit();
        }
    }

    // GET  /personas/index  → listado
    public function index(): void {
        $modeloPersona = $this->modelo('Persona');  // instancia Persona
        $personas = $modeloPersona->getPersonas();

        $this->vista('personas/index', [
            'titulo'   => 'Listado de Dueños',
            'personas' => $personas,  // se convierte en $personas en la vista
        ]);
    }

    // GET + POST  /personas/nueva  → alta
    public function nueva(): void {
        $error = '';
        $ok    = '';

        if ($_SERVER['REQUEST_METHOD'] === 'POST') {

            // 1ª capa: trim() limpia espacios
            $nombre    = trim($_POST['nombre']    ?? '');
            $apellidos = trim($_POST['apellidos'] ?? '');
            $email     = trim($_POST['email']     ?? '');
            $telefono  = trim($_POST['telefono']  ?? '');

            // 2ª capa: validación PHP
            if (empty($nombre) || empty($apellidos)) {
                $error = 'Nombre y apellidos son obligatorios.';

            } elseif (!empty($email) && !filter_var($email, FILTER_VALIDATE_EMAIL)) {
                $error = 'Email no válido.';  // filter_var valida formatos

            } elseif (!empty($telefono) && !preg_match('/^[0-9]{9}$/', $telefono)) {
                $error = 'Teléfono: 9 dígitos.';  // preg_match usa regex

            } else {
                $modeloPersona = $this->modelo('Persona');
                if ($modeloPersona->insertarPersona($nombre, $apellidos, $telefono, $email)) {
                    $ok = 'Persona registrada correctamente.';
                } else {
                    $error = 'Error al guardar.';
                }
            }
        }

        $this->vista('personas/nueva', ['titulo' => 'Nueva Persona',
                                       'error'  => $error, 'ok' => $ok]);
    }
}

Sesiones y Login

HTTP es un protocolo sin estado: cada petición es independiente. Las sesiones permiten "recordar" al usuario entre peticiones guardando datos en el servidor.

Función¿Para qué sirve?
session_start()Inicia o reanuda la sesión. Se llama antes de usar $_SESSION
session_status()Devuelve el estado actual (PHP_SESSION_NONE, PHP_SESSION_ACTIVE...)
session_unset()Limpia todas las variables de sesión
session_destroy()Destruye la sesión por completo
// Controlador Paginas – Login, logout, logged()
class Paginas extends Controlador {

    public function __construct() {
        if (session_status() === PHP_SESSION_NONE) session_start();
    }

    // Se llama al principio de métodos que requieren estar logueado
    public function logged(): void {
        if (!isset($_SESSION['veterinario_id'])) {
            header('Location: ' . RUTA_URL . '/paginas/login');
            exit(); // IMPORTANTE: detiene la ejecución
        }
    }

    // Procesa el formulario de login
    public function login(): void {
        if ($_SERVER['REQUEST_METHOD'] === 'POST') {

            $email = trim($_POST['email'] ?? '');
            $clave = trim($_POST['clave'] ?? '');

            $modeloVet   = $this->modelo('Veterinario');
            $veterinario = $modeloVet->login($email, $clave);  // busca en BD

            if ($veterinario) {
                // ✅ Credenciales correctas: guardar en sesión
                $_SESSION['veterinario_id']     = $veterinario->id;
                $_SESSION['veterinario_nombre'] = $veterinario->nombre;

                header('Location: ' . RUTA_URL . '/paginas/index');
                exit();
            }
            // ❌ Credenciales incorrectas: se muestra error en la vista
        }
        $this->vista('paginas/login', ['error' => 'Email o clave incorrectos']);
    }

    // Cierra la sesión
    public function logout(): void {
        session_unset();   // elimina variables
        session_destroy(); // destruye la sesión
        header('Location: ' . RUTA_URL . '/paginas/login');
        exit();
    }
}

Subida de archivos e imágenes

Para subir archivos, el formulario HTML necesita obligatoriamente enctype="multipart/form-data". Los datos del archivo llegan a PHP en $_FILES.

<!-- En la vista: enctype es OBLIGATORIO para subir archivos -->
<form method="POST" action="..." enctype="multipart/form-data">
    <input type="file" name="foto" accept="image/*">
    <button type="submit">Guardar</button>
</form>

// En el controlador: procesamos la imagen
if (isset($_FILES['foto']) && $_FILES['foto']['error'] === UPLOAD_ERR_OK) {

    $archivo   = $_FILES['foto'];
    $extension = strtolower(pathinfo($archivo['name'], PATHINFO_EXTENSION));

    // Validaciones de seguridad
    if (!in_array($extension, ['jpg', 'jpeg', 'png', 'gif'])) {
        $error = 'Solo se permiten JPG, PNG o GIF.';

    } elseif ($archivo['size'] > 2 * 1024 * 1024) {  // 2 MB
        $error = 'Máximo 2 MB.';

    } else {
        // uniqid() genera nombre único para no sobreescribir archivos
        $nombreArchivo = uniqid('mascota_') . '.' . $extension;
        $rutaDestino   = __DIR__ . '/../../public/img/' . $nombreArchivo;

        if (move_uploaded_file($archivo['tmp_name'], $rutaDestino)) {
            $foto_url = '/public/img/' . $nombreArchivo;
        }
    }
}

Servicios Web y APIs REST

Una API REST es una interfaz que permite a distintas aplicaciones comunicarse entre sí a través de HTTP. En vez de devolver HTML, devuelve datos en formato JSON.

📱
Ejemplo real: Cuando la app de Instagram carga tus fotos, hace una petición a una API REST que le devuelve JSON con la lista de fotos. La app móvil luego muestra ese JSON como le conviene.

Principios fundamentales de REST que debes conocer:

  • Orientación a recursos: todo es un recurso con su URL (persona, mascota, pedido...).
  • Métodos HTTP: GET (leer), POST (crear), PUT (modificar todo), PATCH (modificar parte), DELETE (borrar).
  • Stateless: cada petición es independiente, sin sesiones del servidor.
  • JSON: el formato estándar de respuesta.

¿Cómo encaja REST en MVC?

En nuestro proyecto MVC, la API es simplemente un controlador más que en vez de llamar a una vista HTML, responde con JSON.

CapaEn web normalEn API REST
ModeloIgual: accede a la BDIgual: accede a la BD
ControladorLlama a la vistaDevuelve JSON con json_encode()
VistaHTML❌ No existe. El JSON ES la respuesta
🔑
La URL /api/personas llega al Core, que instancia el controlador Api y llama al método personas(). Exactamente igual que con los controladores normales.
3.4

Autenticación HTTP Basic

Las APIs no usan sesiones. Se autentican con cada petición. La autenticación HTTP Basic envía usuario y contraseña codificados en Base64 en la cabecera Authorization.

⚠️
HTTP Basic en producción solo debe usarse sobre HTTPS. La codificación Base64 NO es cifrado: es reversible. En el examen lo usamos porque es el método más simple de entender.
// El cliente envía esta cabecera:
// Authorization: Basic YXBpY2xpbmljYTpjbGluaWNhYXBp
// Que es Base64 de "apiclinica:clinicaapi"

private function autenticarBasic(): void {
    $usuario_api = 'apiclinica';
    $clave_api   = 'clinicaapi';

    // PHP decodifica automáticamente la cabecera Basic y rellena estas vars
    $usuario = $_SERVER['PHP_AUTH_USER'] ?? '';
    $clave   = $_SERVER['PHP_AUTH_PW']   ?? '';

    if ($usuario !== $usuario_api || $clave !== $clave_api) {
        http_response_code(401);  // 401 Unauthorized
        header('WWW-Authenticate: Basic realm="API Clínica"');
        header('Content-Type: application/json; charset=utf-8');
        echo json_encode(['error' => 'No autorizado']);
        exit();  // detenemos aquí
    }
}
3.5

Controlador API completo

class Api extends Controlador {

    public function __construct() {
        $this->autenticarBasic();  // si no pasa, devuelve 401 y exit
    }

    // Método helper: responde JSON y detiene ejecución
    private function jsonResponse(array $datos, int $codigo = 200): void {
        http_response_code($codigo);
        header('Content-Type: application/json; charset=utf-8');
        echo json_encode($datos, JSON_UNESCAPED_UNICODE);
        exit();
    }

    // GET  /api/personas  → lista
    // POST /api/personas  → crear
    public function personas(): void {
        $metodo = $_SERVER['REQUEST_METHOD'];

        if ($metodo === 'GET') {
            $personas = $this->modelo('Persona')->getPersonas();
            // Convertimos objetos a arrays para json_encode
            $resultado = array_map(fn($p) => (array)$p, $personas);
            $this->jsonResponse($resultado, 200);

        } elseif ($metodo === 'POST') {
            // Leemos el JSON del body de la petición
            $body      = json_decode(file_get_contents('php://input'), true);
            $nombre    = trim($body['nombre']    ?? '');
            $apellidos = trim($body['apellidos'] ?? '');

            if (empty($nombre) || empty($apellidos)) {
                $this->jsonResponse(['error' => 'Nombre y apellidos obligatorios'], 400);
            }

            $ok = $this->modelo('Persona')->insertarPersona(
                      $nombre, $apellidos,
                      trim($body['telefono'] ?? ''),
                      trim($body['email']    ?? '')
                  );

            $this->jsonResponse(
                $ok ? ['mensaje' => 'Dueño creado'] : ['error' => 'Error al crear'],
                $ok ? 201 : 500
            );

        } else {
            $this->jsonResponse(['error' => 'Método no permitido'], 405);
        }
    }

    // DELETE /api/mascota/{id}  → eliminar mascota
    public function mascota(int $id): void {
        if ($_SERVER['REQUEST_METHOD'] !== 'DELETE') {
            $this->jsonResponse(['error' => 'Método no permitido'], 405);
        }

        $modelo  = $this->modelo('Mascota');
        $mascota = $modelo->getMascotaPorId($id);

        if (!$mascota) {
            $this->jsonResponse(['error' => "Mascota {$id} no encontrada"], 404);
        }

        $ok = $modelo->eliminarMascota($id);
        $this->jsonResponse(
            $ok ? ['mensaje' => "Mascota {$id} eliminada"] : ['error' => 'Error'],
            $ok ? 200 : 500
        );
    }
}
3.6

Probar la API con curl y archivo .http

Hay dos formas de probar la API sin necesitar un frontend:

Opción A: curl desde la terminal

curl es una herramienta de línea de comandos para hacer peticiones HTTP.

# GET: obtener todas las personas
curl -u apiclinica:clinicaapi \
     http://localhost/mvcrecuperacion/public/api/personas

# POST: crear nueva persona (enviamos JSON en el body)
curl -u apiclinica:clinicaapi \
     -X POST \
     -H "Content-Type: application/json" \
     -d '{"nombre":"Pedro","apellidos":"Sanz","email":"pedro@test.com"}' \
     http://localhost/mvcrecuperacion/public/api/personas

# DELETE: eliminar mascota con id 2
curl -u apiclinica:clinicaapi \
     -X DELETE \
     http://localhost/mvcrecuperacion/public/api/mascota/2

Opción B: archivo .http (VS Code + extensión REST Client)

Instala la extensión REST Client en VS Code. Crea un archivo api_tests.http y haz clic en "Send Request" encima de cada bloque:

Resumen: lo que más cae en el examen

OOP

  • public = todos, protected = yo y mis hijas, private = solo yo.
  • extends para heredar de una clase, implements para implementar una interfaz.
  • Las clases abstract no se instancian. Sus métodos abstract obligan a la hija a implementarlos.
  • Los trait son bloques de código reutilizable que se "pegan" con use.
  • El namespace organiza el código. Siempre al principio del archivo. Cambiarlo → composer dump-autoload.

MVC

  • Modelo: solo SQL con PDO y sentencias preparadas (bind()). Nunca HTML.
  • Controlador: recoge $_POST, valida con trim() + filter_var() + preg_match(), llama al modelo, llama a la vista.
  • Vista: solo HTML + foreach. Siempre htmlspecialchars() para mostrar datos.
  • Sesión: session_start() antes de usar $_SESSION. Login → guardar en $_SESSION. Logout → session_unset() + session_destroy().
  • Subida de archivos: enctype="multipart/form-data" en el form. $_FILES['foto']. move_uploaded_file() para moverlo.

APIs REST

  • La API es un controlador que responde JSON, no HTML.
  • Leer el método HTTP con $_SERVER['REQUEST_METHOD'].
  • Leer el JSON del body con json_decode(file_get_contents('php://input'), true).
  • Responder con http_response_code($codigo) + header('Content-Type: application/json') + json_encode($datos).
  • Autenticación Basic: $_SERVER['PHP_AUTH_USER'] y $_SERVER['PHP_AUTH_PW'].
  • Códigos: 200 (ok), 201 (creado), 400 (datos mal), 401 (sin auth), 404 (no existe), 405 (método no permitido), 500 (error BD).
